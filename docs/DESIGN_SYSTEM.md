# 避坑指南设计系统

> 版本：1.0
> 设计方向：Neo Editorial Utility / 新编辑实用主义
> 视觉基线：会议 1.5A 已确认 V2
> 适用范围：首页、搜索、帖子详情、投稿、登录、个人页及其共用组件

## 1. 设计使命

避坑指南不是“曝光墙”，也不是把焦虑包装成流量的内容平台。它要把分散的个人经历、规则变化和行动方法，转化为简洁、可追溯、能执行的公共知识。

视觉系统必须同时满足四个目标：

1. **一眼有辨识度**：像一本正在发生的独立文化杂志，而不是通用社区模板。
2. **第一眼可信**：大胆但不轻浮，信息来源、适用条件、更新时间和争议状态永远清楚。
3. **三秒找到行动**：用户先看到“现在该做什么”，再决定是否阅读完整经历。
4. **长期可使用**：不依赖短命潮流、昂贵字体、纯装饰动画或难以维护的视觉特效。

品牌主张：

> 把前人的经验，留成看得见的路标。

设计判断句：

> 版面可以生猛，事实必须克制；手绘可以不完美，交互必须准确。

## 2. 视觉语言

### 2.1 核心气质

- **新编辑主义**：大标题、紧字距、非对称网格、明确分栏、留白与局部拥挤形成节奏。
- **印刷实物感**：硬边框、偏移阴影、丝网网点、炭笔或蜡笔痕迹、有限套色。
- **公共路标感**：颜色提示内容类型、风险和行动，不用于情绪煽动。
- **真实手作感**：允许轻微错版、粗糙边缘和裁切，但禁止随机噪点堆砌。
- **内容先行**：任何装饰都不得压过标题、适用条件、先做事项和可信度信息。

### 2.2 视觉节奏

- 每个首屏只允许一个主要视觉动作：大标题、主插画或搜索框三者选一为视觉中心。
- 每个页面最多使用两个高饱和强调色，其中一个必须承担明确语义。
- 大面积背景以暖纸色或白色为主；高饱和色块单次面积原则上不超过当前视口的 30%。
- 组件采用黑色硬边与偏移阴影，信息密集区域减少阴影，只保留分隔线。
- 不通过颜色数量制造“热闹”，通过字号、位置、尺度和留白制造编辑感。

## 3. 设计令牌

所有页面和组件只能使用设计令牌。新增颜色、字号、圆角或阴影前，必须先说明现有令牌不能满足的语义。

### 3.1 色彩

| 令牌 | 色值 | 用途 |
|---|---:|---|
| `paper` | `#F7F2E7` | 全局暖纸背景、降低纯白屏幕的冷感 |
| `surface` | `#FFFDF8` | 卡片、表单、浮层、正文表面 |
| `ink` | `#111827` | 主文字、边框、图标、偏移阴影 |
| `ink-muted` | `#45505F` | 次级说明、元数据；不得用于小于 14px 的关键内容 |
| `gray` | `#E7E4DB` | 禁用背景、分隔区域、骨架屏 |
| `cobalt` | `#3157FF` | 主行动、链接、规则类内容、焦点环 |
| `cobalt-dark` | `#1638C7` | 主按钮悬停、已访问状态的深色变体 |
| `cobalt-pale` | `#E8ECFF` | 规则卡片背景、信息提示 |
| `acid` | `#B9FF66` | 公开案例、成功反馈、贡献与成长；文字使用 `ink` |
| `acid-pale` | `#E9FFC9` | 案例卡片背景、低强度成功状态 |
| `orange` | `#FF6B35` | 行动清单、临近过期、中高风险提醒 |
| `orange-pale` | `#FFE7DD` | 清单卡片背景、温和警示 |
| `violet` | `#6B4EFF` | 争议、反证、复核中的专属语义 |

语义限制：

- `cobalt`、`orange` 和 `violet` 上的常规小字号文字优先使用白色或经过对比度验证的深色变体。
- `acid` 只能搭配 `ink`，不得搭配白字。
- 高风险不能只用红色表达，必须同时出现“高风险”文本、图标或形状。
- “已核验”不能只依靠绿色；必须展示核验日期与证据入口。
- “已过期”使用低饱和表面、明确文字和时间，不使用降低整体透明度的方式隐藏内容。

### 3.2 字体与排版

字体栈：

```text
ui-sans-serif, -apple-system, BlinkMacSystemFont, "SF Pro Display",
"PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif
```

不引入缺少完整中文字形的“时装字体”。潮流感来自版式，不来自牺牲中文阅读质量。

| 层级 | 桌面 | 移动 | 字重 | 行高 | 用途 |
|---|---|---|---:|---:|---|
| Display | 64–76px | 42–50px | 820 | 1.05 | 首页主张、详情主标题 |
| H1 | 48–64px | 36–44px | 820 | 1.08 | 页面标题 |
| H2 | 36–44px | 28–34px | 820 | 1.12 | 主章节标题 |
| H3 | 22–24px | 20–22px | 680–820 | 1.25 | 卡片标题、子章节 |
| Lead | 18–20px | 17–18px | 400–550 | 1.55 | 引导说明、摘要 |
| Body | 17px | 16px | 400 | 1.65 | 正文 |
| Meta | 12–14px | 12–14px | 550–680 | 1.5 | 标签、日期、来源 |

排版规则：

- 中文正文单行理想长度为 22–36 个汉字，正文容器最大宽度 `720px`。
- Display 与 H1 可使用 `-0.04em` 至 `-0.065em` 字距；正文不得使用负字距。
- 英文眉题可全大写并增加字距，但必须配有中文信息，不得承担唯一语义。
- 禁止使用超过两种字重表达同一信息层。
- 长数字、日期、价格、地区和风险等级应避免被断行拆分。

### 3.3 间距

基础单位为 `4px`：

```text
4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80
```

- 控件内部：`8–16px`
- 卡片内部：移动端 `16–20px`，桌面端 `20–24px`
- 卡片间距：移动端 `16px`，平板 `20px`，桌面 `24px`
- 页面水平边距：移动端 `16px`，平板 `24px`，桌面 `32px`
- 章节垂直间距：移动端 `48–64px`，桌面 `64–96px`
- 信息组内间距必须小于信息组之间的间距，禁止所有元素等距排列。

### 3.4 圆角、边框与阴影

| 令牌 | 数值 | 用途 |
|---|---:|---|
| `radius-sm` | `4px` | 输入框、小按钮、提示条 |
| `radius-md` | `8px` | 弹窗、下拉菜单、普通容器 |
| `radius-lg` | `12px` | 少量柔和内容容器 |
| `radius-pill` | `999px` | 标签、筛选项、头像状态 |
| `border-thin` | `1px solid #111827` | 次级分隔、正文模块 |
| `border-strong` | `2px solid #111827` | 卡片、主按钮、关键输入 |
| `shadow-sm` | `5px 5px 0 #111827` | 卡片、按钮 |
| `shadow-lg` | `12px 12px 0 #111827` | 主视觉、重要弹层 |

主内容卡片优先使用直角或 `4px` 小圆角。禁止所有组件统一为大圆角“胶囊”，也禁止使用模糊、漂浮、无边界的 SaaS 阴影。

悬停时卡片最多位移 `2px`；按下时回到原位并缩短阴影。阴影不可成为状态唯一提示。

### 3.5 图标

- 使用统一的单色线性或实心几何图标，线宽与组件边框协调。
- 图标尺寸仅使用 `16 / 20 / 24 / 32px`。
- 图标不得代替“已过期”“有争议”“收藏”等关键文字。
- 纯装饰图标使用空替代文本或 `aria-hidden="true"`。
- 自定义图标必须保持黑墨硬边与简化路标语法，不混入拟物、3D 或彩色 emoji。

## 4. 手绘资产使用边界

### 4.1 可以使用

- 首页品牌主视觉、分类入口封面、空状态、贡献勋章和低频活动页。
- 炭笔、蜡笔、丝网网点、纸张纤维、套色偏移和人工裁切。
- 有明确叙事的动作：指路、标记、核对、托举、修补、共同绘制路线。
- 有限色：每张资产最多使用 `ink + paper + 2` 个品牌强调色。
- 局部不规则，但人物比例、手部、文字和物体结构必须可信。

### 4.2 不得使用

- 帖子正文、表单字段、审核状态、法律或安全警告的背景。
- 用插画遮挡来源、日期、风险等级或行动步骤。
- AI 常见的无意义图标云、漂浮卡片、发光球体、复杂管线和随机小人。
- 无逻辑的手指、肢体、文字乱码、重复人物、伪签名或假装扫描的证明材料。
- 同一页面堆叠三种以上笔触，或同时使用水彩、3D、黏土、渐变网格等不相容风格。

### 4.3 质量验收

每张手绘资产必须通过：

1. 缩小到 `320px` 宽仍能读懂主要动作；
2. 黑白显示仍能区分主体和背景；
3. 不依赖图片内文字传达必要信息；
4. 人物和物体没有结构性错误；
5. 与页面中真实内容存在具体关系，而不是泛化“社区氛围”；
6. 裁掉资产后，页面任务仍可完成。

## 5. 三种正式内容卡片

所有卡片遵循同一阅读顺序：

> 类型与状态 → 标题 → 适用条件 → 立即行动 → 可信度 → 社区反馈 → 进入详情

列表卡片必须让用户不打开详情也能获得一个安全、有限、可执行的结论。

### 5.1 公开案例卡

语义：真实投稿或经公开资料整理的具体经历，强调“在什么条件下发生了什么”。

视觉：

- 背景 `acid-pale`
- 类型标签 `acid + ink`
- 顶部黑色硬边或手绘短线作为案例识别符

层级：

1. `公开案例` + 审核状态 + 风险等级
2. 结果导向标题，避免情绪化定罪
3. 地区 / 时间 / 对象 / 场景
4. **先做**：一个最优先动作
5. 证据类型、核验日期、适用边界
6. 有用数、补充数、反证数
7. `查看完整经历`

不得出现：未经裁决的违法定性、完整姓名、联系方式、合同编号、对话截图原图或“所有人都会”等绝对结论。

### 5.2 规则更新卡

语义：政府、学校、平台、机构或服务规则的变化，强调时效和来源。

视觉：

- 背景 `cobalt-pale`
- 类型标签 `cobalt + white`
- 来源和更新时间必须位于首屏可见区域

层级：

1. `规则更新` + `已核验 / 待复核 / 已过期`
2. 变化本身，而不是吸睛标题
3. 生效地区 / 生效日 / 适用人群
4. **先做**：如何核对或准备
5. 官方来源名称、最近核验日期、下次复核日期
6. 争议或例外数量
7. `查看规则与原始来源`

过期规则仍保留历史价值，但列表默认降权，并显示“请勿直接照做”。

### 5.3 行动清单卡

语义：用户在付款、签字、提交、出发或确认前可以完成的检查步骤。

视觉：

- 背景 `orange-pale`
- 类型标签使用 `orange` 或高对比深色变体
- 清单进度是辅助信息，不能伪造“完成即安全”

层级：

1. `行动清单` + 风险等级
2. 任务型标题
3. 使用时点 / 对象 / 地区 / 版本
4. **第一项** + 总步骤数
5. 依据、适用限制、更新时间
6. 收藏数、完成反馈、纠错数
7. `打开完整清单`

清单步骤使用动词开头，每步只包含一个动作；无法验证的建议必须标为“经验建议”，不得伪装成规则。

## 6. 页面结构与响应式布局

断点用于内容重排，不用于识别设备：

| 范围 | 画布与网格 |
|---|---|
| `< 640px` | 单列；左右 `16px`；底部主导航 |
| `640–1023px` | 6 列；左右 `24px`；卡片 1–2 列 |
| `≥ 1024px` | 12 列；左右 `32px`；内容最大宽度 `1280px` |
| `≥ 1440px` | 保持最大宽度，增加外部留白，不无限拉长文本 |

### 6.1 首页

桌面：

- 顶部导航：品牌、搜索入口、分类、发布、登录或头像。
- 首屏采用约 `7:5` 非对称网格：左侧价值主张与大搜索框，右侧 V2 主视觉。
- 搜索框必须允许未登录用户直接搜索。
- 首屏后依次为：高风险及时提醒、五大领域、精选卡片、近期规则更新、社区贡献说明。
- 首页卡片桌面 3 列，第二张可错位 `24–28px` 形成编辑节奏；错位不得影响键盘顺序。

移动：

- 首屏先显示主张与搜索，插画后置并裁切为横幅。
- 高频分类横向滚动，但同时提供“全部分类”入口。
- 主卡片单列；不使用瀑布流，避免阅读顺序和焦点顺序混乱。
- 底部导航包含：首页、搜索、发布、收藏、我的。

### 6.2 搜索与筛选

桌面：

- 顶部为持久搜索框；左侧筛选栏宽 `240–280px`；右侧结果区。
- 筛选顺序：场景、问题类型、地区、风险等级、内容类型、状态、时间。
- 当前筛选以可移除标签显示，并提供“清空全部”。
- 排序默认“综合可信度”，可选“最新核验”“离我最近”“讨论最多”。

移动：

- 搜索框吸顶；筛选与排序使用底部抽屉。
- 抽屉顶部展示已选数量，底部固定“查看 N 条结果”和“重置”。
- 结果更新不得导致页面突然跳到顶部；用户确认筛选后再刷新。
- 筛选项触控高度至少 `44px`，长列表支持组内搜索。

### 6.3 帖子详情

桌面：

- 主栏 `minmax(0, 720px)`，侧栏 `280–320px`。
- 主栏顺序：状态带、标题、适用条件、行动摘要、完整内容、证据与来源、修订记录、评论与反证。
- 侧栏：收藏、分享、可信度说明、更新时间、纠错或否认入口；滚动吸顶但不得遮挡页脚。

移动：

- 状态、标题、适用条件和“先做”必须在首个完整屏幕内优先出现。
- 收藏、分享、纠错放入底部行动栏；最多显示 3 个直接操作，其余进入菜单。
- 长证据折叠展示摘要，但“来源名称、日期、状态”不得折叠。
- 评论和反证分区，不把反证混在普通情绪评论中。

### 6.4 投稿

采用分步问题树，而不是一次展示长表单：

1. 选择内容类型；
2. 说明发生了什么；
3. 明确时间、地区、对象与适用条件；
4. 给出用户可执行的行动；
5. 上传并脱敏证据；
6. 预览卡片；
7. 确认授权与提交审核。

桌面使用左侧步骤导航、右侧表单；移动端顶部显示“第 N / 7 步”和短标题。每一步只设置一个主要按钮。

草稿自动保存时显示具体时间。离开未保存内容前必须提醒。上传界面必须明确说明会自动脱敏什么、仍需用户检查什么。

### 6.5 登录与注册

- 未登录用户可浏览、搜索、筛选和查看详情；收藏、评论、投稿时再触发登录。
- 登录页保持克制：一句价值说明、第三方方式、邮箱或手机号方式、隐私说明。
- 第三方登录按钮只有在真实接入并可用时才展示；不得使用假按钮或“即将上线”占据主要区域。
- 登录弹层触发后保留用户原任务，成功后回到原帖子、评论草稿或投稿步骤。
- 错误提示放在对应字段附近，并在表单顶部提供可聚焦的错误摘要。

### 6.6 个人页

信息层级：

1. 头像、名称、等级、贡献勋章；
2. 有效贡献数据：已发布、被收藏、帮助反馈、纠错采纳；
3. 投稿、收藏、评论、草稿、审核进度标签页；
4. 勋章解释与获得条件；
5. 隐私、通知与账号设置。

积分不得暗示经验“绝对正确”。等级代表社区贡献和持续维护，不代表专业资质。风险类内容不展示刺激竞争的连续打卡、倒计时或排行榜羞辱。

## 7. 组件状态

### 7.1 加载

- 首次加载使用与最终布局等高的骨架屏，减少布局跳动。
- 骨架颜色使用 `gray` 与 `paper`，不使用高频闪烁或扫光。
- 操作提交使用按钮内进度文字，例如“正在提交…”，并防止重复提交。
- 超过 10 秒仍未完成时，显示当前阶段、重试和保存草稿选项。
- 对屏幕阅读器使用简洁的 `aria-live="polite"` 状态，不重复播报每个骨架元素。

### 7.2 空状态

空状态必须回答三个问题：为什么为空、用户现在能做什么、是否需要调整范围。

- 搜索无结果：展示当前关键词和筛选条件，提供清除部分筛选、订阅更新或发起求助。
- 无收藏：推荐先搜索，不用“这里空空如也”等无信息文案。
- 无投稿：解释一次有效投稿能如何帮助别人，并提供内容标准入口。
- 可以使用单幅低复杂度手绘资产，但主行动始终是文字按钮。

### 7.3 错误

- 错误文案结构：发生了什么 + 是否保存 + 下一步。
- 表单错误必须精确到字段，不使用“参数错误”“操作失败”等内部语言。
- 网络错误保留用户输入，并提供重试。
- 权限错误解释需要何种身份和原因，不诱导重复点击。
- 404 提供搜索和返回上一页；500 提供错误编号，但不展示堆栈或敏感信息。
- 高风险流程失败时不得显示轻佻插画、玩笑或庆祝色。

### 7.4 内容状态

| 状态 | 显示要求 |
|---|---|
| 已核验 | 核验日期、证据类型、查看依据 |
| 待复核 | 原因、预计处理或用户可补充内容 |
| 有争议 | `violet` 标识、争议摘要、反证入口 |
| 已过期 | 过期日期、原因、新版本入口或“暂无替代” |
| 已纠错 | 修订摘要、前后差异、修订日期 |
| 已撤回 | 撤回主体、原因类别；保护隐私时不披露细节 |

“投诉”“否认”属于不同动作：投诉针对违规或伤害，否认针对事实或适用性争议。界面和审核路径必须分别命名。

## 8. 移动端交互

- 所有主要触控目标至少 `44 × 44px`，相邻危险操作间距至少 `8px`。
- 不依赖悬停展示必要内容。
- 支持系统返回；关闭抽屉或弹层后焦点回到触发控件。
- 底部行动栏避开安全区域，使用 `env(safe-area-inset-bottom)`。
- 键盘弹出时，当前输入与错误提示保持可见；提交按钮不得被键盘永久遮挡。
- 横向滑动仅用于分类或标签短列表，卡片正文不使用横向轮播。
- 下拉刷新不是唯一刷新方式；提供可访问的“刷新”按钮或状态。
- 收藏、点赞等轻量操作提供即时反馈；投稿、删除、投诉等高成本操作必须确认结果。
- 分享优先调用系统分享能力，同时提供复制链接并反馈“已复制”。
- 尊重系统字体放大，放大至 200% 时不得截断关键内容或阻止操作。

## 9. 动效

- 时长仅使用 `100ms` 与 `180ms`，缓动 `cubic-bezier(.2,.9,.2,1)`。
- 动效用于说明状态变化、层级和操作结果，不用于持续吸引注意。
- 卡片悬停、按钮按下、抽屉进出和状态更新可动；正文、风险提示和来源信息不自动移动。
- 遵循 `prefers-reduced-motion: reduce`：关闭位移、缩放、视差和自动滚动，只保留必要的瞬时状态切换。
- 禁止滚动劫持、首屏强制开场动画、无限漂浮装饰和自动播放视频。

## 10. WCAG 无障碍基线

目标：所有核心流程满足 **WCAG 2.2 AA**。

### 10.1 感知

- 正文与背景对比度至少 `4.5:1`；大字至少 `3:1`；控件边界和状态图形至少 `3:1`。
- 信息不得仅依赖颜色、位置或形状表达。
- 图片提供与任务相关的替代文本；装饰图隐藏；证据截图需提供文字摘要。
- 视频提供字幕，重要音频提供文字稿。
- 页面缩放至 200%、窄至 `320 CSS px` 时不出现阻断性双向滚动。

### 10.2 操作

- 所有功能支持键盘完成，焦点顺序与视觉阅读顺序一致。
- 提供“跳到主要内容”链接。
- 焦点环使用至少 `2px` 的 `cobalt` 外框与 `2px` 间隔，不得移除。
- 弹层正确管理初始焦点、焦点约束与关闭后的焦点返回。
- 不使用单字符快捷键；复杂拖拽必须提供点击或键盘替代。
- 会话超时、上传失败或网络重连不得丢失已填写内容。

### 10.3 理解

- 页面使用唯一且描述性的 H1，标题层级不跳跃。
- 表单字段有持久可见的标签；占位符不能代替标签。
- 必填、格式、隐私用途和示例在输入前说明。
- 错误提示指出位置、原因和修复方法，并能被屏幕阅读器关联。
- 风险、核验、过期和争议词汇全站一致，不使用同义词制造误解。
- 登录、投诉、撤回、删除等结果在执行前说明。

### 10.4 稳健

- 优先使用原生语义元素：`header`、`nav`、`main`、`article`、`button`、`form`。
- 自定义组件遵循对应 ARIA 模式，但不以 ARIA 修补错误 HTML。
- 动态结果数量、保存成功和错误摘要使用适当 live region，避免重复播报。
- 自动化检查不能替代键盘、屏幕阅读器、放大和高对比模式人工测试。

### 10.5 发布前无障碍验收

- 仅用键盘完成搜索、筛选、收藏登录回跳、评论和投稿。
- 使用 VoiceOver 或同类屏幕阅读器完成至少一次核心流程。
- 测试 200% 缩放、系统大字体、减少动态、高对比或强制颜色模式。
- 验证每种状态在灰度下仍可辨认。
- 验证错误发生后输入不丢失、焦点移动合理、修复路径清晰。

## 11. 文案与视觉共同规则

- 标题描述“条件 + 风险或结果”，不使用“震惊”“千万别”“血泪教训”等流量词。
- 行动建议使用动词开头，并说明适用边界。
- 不把个案写成普遍规律，不把相关性写成因果。
- 不以视觉权威感掩盖证据不足；证据较弱时必须降低确定性表达。
- 争议状态不是惩罚色，过期状态不是删除；都应保留理解和修正知识的路径。
- 成就与积分奖励持续贡献、更新和纠错，不奖励冲突、曝光或情绪强度。

## 13. 设计验收清单

每个页面合并前必须回答：

1. 未登录用户是否能完成浏览、搜索、筛选和查看详情？
2. 用户能否在三秒内找到适用条件、风险状态和第一步行动？
3. 颜色是否承担明确语义，且没有成为唯一提示？
4. 来源、核验日期、争议和过期信息是否在应有层级可见？
5. 是否只使用了一个主强调色和有限的手绘资产？
6. 手机 `320px`、常用桌面宽度和 200% 缩放是否可完成任务？
7. 键盘焦点是否可见、顺序是否正确、弹层是否能安全退出？
8. 加载、空、错误、无权限和过期状态是否都有清晰下一步？
9. 是否出现负面词清单中的模板化或误导性模式？
10. 移除装饰后，页面结构、可信度和行动路径是否仍然成立？

满足以上规则，才算延续 V2；仅复制颜色和硬阴影，不算延续 V2。
